## Verified with no finding

These were tested, not assumed. Each is a section of the audit brief that came back clean.

- **Command injection (2.1) — none.** All six desktop spawn sites use `QProcess::start(program, QStringList)` (argv, never a shell string); `setNativeArguments()` — the one Qt API that would bypass Windows quoting — is never called; yt-dlp gets a literal `--` before every URL. No server-side process spawning exists at all.
- **SSRF (2.2) — policy holds.** 12 vectors driven through the live dashboard, all refused: `127.0.0.1`, `localhost:22`, `169.254.169.254`, `10.x`, `192.168.x`, `172.16.x`, `[::1]`, `[fc00::1]`, `100.64.x`, `file://`, `printer.local`, and `user:pass@`. Redirect hops are covered on both untrusted entry points (`IpcServer` and `addRemoteDownload` both pass `publicNetworkOnly=true`).
- **IDOR (2.6) — closed, verified live not just read.** Gave user B a real Pro subscription and a real `license_activations` row, then had user A call `DELETE /api/user/devices/<B's real activation id>`: **404, and B's `revoked_at` stayed NULL**. Six guessed ids all 404; six team member/invite ids all 403; seven account routes all 401 anonymously; a customer token refused by all five admin/root routes.
- **Error hygiene (2.6) — clean.** Seven malformed / traversal / oversized probes returned no stack trace, filesystem path, driver error or framework banner; the `{ok:false,error:{code,message}}` envelope held throughout; no `X-Powered-By`.
- **XSS in the web apps (2.6) — none.** Zero `dangerouslySetInnerHTML` / `innerHTML` / `eval` anywhere; the extension avoids `innerHTML` deliberately because of YouTube's Trusted Types CSP.
- **Torrent path traversal (2.4) — contained.** Five hand-built malicious torrents: `../../../../etc/passwd` in the file list, `../../../../tmp/pwned` as the name, NUL bytes in path elements, a 200k-piece bomb, a 200k-file bomb. Resolved every path libtorrent would write against `save_path`: **0 escaped.** Traversal segments are rewritten to `_`, the piece bomb parsed in 47 ms, the file bomb was refused outright.
- **Resource exhaustion (2.4) — graceful.** A 500-item batch queued in 5.6 s; the app stayed responsive (18–272 ms) and did not crash. `expandPattern` refuses a range wider than 10,000 and `kMaxBatchItems` caps the total. 13 tiered rate limiters on the server, the security-critical ones counted in MySQL.
- **Resume after interruption (Phase 1) — no corruption.** `kill -9` at 3,594,840 / 19,421,688 bytes; on restart the app resumed by itself and finished, and the final **SHA-256 matched exactly**. Segment offsets and `ranges_supported` survive in the DB across a hard kill.
- **Pause / resume / integrity (Phase 1).** A 36 MB installer paused at 24.7 MB (bytes frozen), resumed from there (not zero), completed, and its **SHA-256 matched the publisher's**. Auto-categorisation filed it under `Programs/`; collision avoidance produced `… (1).deb` instead of overwriting the existing file.
- **HLS end to end (Phase 1).** Mux's public test stream → **486 MB MP4, H.264 1920×1080 + AAC, 634.6 s**, frames decode. Filed under `Video/`.
- **Responsive layout (Phase 3) — no overflow.** 21 public pages × 5 viewports (320 / 390 / 768 / 1280 / 1920): no page scrolls sideways. The mobile hamburger opens and navigates. Detector proven non-vacuous against an injected 2000 px element.
- **Broken links (Phase 3).** Every internal `to=`/`href=` in the app resolves to a defined route. External links were the High finding, now fixed.

## Notes for whoever picks this up

- Build: `cmake -B build-audit -G Ninja -DNEXA_BUILD_TESTS=ON -DNEXA_DEV_BUILD=ON`, then run tests under `xvfb-run -a ctest --test-dir build-audit` — several suites construct Qt widgets and need a display.
- Backend integration suites need a throwaway MySQL; recipe in `backend/test/README.md`. Shut it down and remove the datadir afterwards, as that file warns.
- Driving the app headlessly: `xvfb-run -a env HOME=… TMPDIR=… XDG_CONFIG_HOME=… XDG_DATA_HOME=… QT_QPA_PLATFORM=xcb ./build-audit/nexa --dashboard=<port> --dashboard-token=…`. Isolate **`XDG_DATA_HOME` too** — the SQLite database lives under `AppDataLocation`, so without it a test instance writes into the real install's history. Set `ui/confirmBeforeStart=false` in the isolated `Nexa.conf` or every handoff sits in `Paused` waiting for a dialog nobody can click.
- `.gitignore` now covers `build*/`, so an out-of-tree build directory cannot be committed by accident. (Note git treats a trailing `# comment` on a pattern line as part of the pattern — the comment is on its own line.)
- Two new test files are additions, not edits: `tests/EngineHelpersTest.cpp` gained two cases, `ndm-website/frontend/e2e/responsive.spec.js` is new.
